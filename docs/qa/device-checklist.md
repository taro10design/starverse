# 実機確認チェックリスト

リリース前や操作・通信を変えたときに、実機とブラウザで確認するための表。自動テストでは確かめられない「手で触った感じ」を確かめる。

## ルール

1. エミュレーション（開発者ツールの端末表示、シミュレータ、リモートデスクトップ）は実機の代わりにならない。触覚、音の自動再生制限、セーフエリア、ピンチ、電波の切れ方は、実機でしか分からない。エミュレーションで確かめた場合は、結果欄に「エミュレーション」と書き、実機の確認とは別に扱う。
2. 確認した日付・端末・OS（とブラウザのバージョン）を結果欄に必ず書く。書式: `YYYY-MM-DD / 端末名 / OS とバージョン / OK か NG`。書けないものは確認したことにしない。
3. 結果は `OK`、`NG`（何が起きたかを書く）、`対象外`（理由を書く）のどれかにする。確認していない項目は「未確認」のままにする。
4. NG が出たら、再現手順を [TODO](../TODO.md) か issue に書く。仕様と食い違うなら [docs/specs](../specs/README.md) を先に直す。
5. 自動テストで確かめられる項目は載せない。仕様書の受け入れ条件のうち「手動」のものがこの表に対応する。

## 対象

| 区分 | 対象 |
| --- | --- |
| スマホ | iOS Safari / Android Chrome |
| デスクトップ | Chrome / Firefox / Safari |

各表の結果欄には、対象ごとの結果を `対象: 日付 / 端末 / OS / 結果` の形で書き足す。タッチ・触覚・向きは主にスマホ、キーボードは主にデスクトップを対象にする。
