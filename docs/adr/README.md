# 設計判断の記録（ADR）

## 目的

「なぜそう作ったか」を残すための短い記録です。コードを読むだけでは分からない、
検討した選択肢・決めた理由・受け入れた欠点を、1件1ファイルで書きます。
全体の構成は `docs/architecture.md`、拡張の手順は `docs/extending.md`、未着手の課題は `docs/TODO.md` を見てください。

## 書き方のルール

- ファイル名は `NNNN-短い名前.md`。番号は4桁の連番で、欠番にも使い回しにもしない。
- 形式は MADR 風。`背景` / `検討した選択肢` / `決定` / `結果` / `参考` の順に書く。
- 1件は40〜70行を目安にする。コード参照は実在するファイル・関数名だけを書く。
- 数値は出典のあるものか、実測したものだけを書く。
- 決定を変えるときは、既存の ADR を書き換えず、新しい ADR を追加して、古い ADR の状態を「置き換え済み（NNNN）」にする。
- 状態は 提案 / 採用 / 置き換え済み のいずれか。
